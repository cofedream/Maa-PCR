## 失败原帧

黎明界的 Python Owner 和日常的 GUI Owner 分别收集原生识别 ID。原生回调只保留 ID；原图查询与复制放在原生任务结束后的 Owner 安全位置。日常 Agent 继续借用 Context，不创建、绑定或销毁 Tasker，也不在回调中反查 Tasker。

Python Owner 暂存最后两次识别的独立图片副本，最终失败时才写盘。GUI Owner 在日常根任务终止失败后读取最后两个识别记录。普通 Or/And 分支未命中及成功任务不生成失败包。Owner 等待中断、没有识别 ID、缓存淘汰、编码或磁盘异常时，保留原结果，并记录图片缺失或本地警告；不会补截图冒充原帧。

新增证据保存到程序根目录 `.runtime/ocr-failures/<run_id>/`。两端采用 `pcr-ocr-failure-v1`：Owner、run/task/reco ID、节点、原始识别词与分数、当时节点规则、资源及模型 SHA-256、原图与可取得的精确 ROI 裁剪。原始识别结果可能包含账号信息，只保存在本地。标准诊断导出沿用白名单，不递归带出这里的图片。

默认原生图片缓存为 16 帧，写入队列最多两帧，每个运行新增图片上限 16 MiB，新增诊断目录总量上限 512 MiB。跨进程独占额度锁防止同时超额写图；锁占用或遗留时停止图片写入，保留缺失说明。额度耗尽只警告并停止新图，不自动删历史。Python 结束时最多等写入线程 0.8 秒；磁盘长期阻塞或进程被强制结束可能丢失尚未写完的证据，不能承诺每次失败都有原图。

## 模型评测

在完整开发 Python 3.13 环境运行：

```powershell
python -X utf8 -B scripts/ocr_benchmark.py --samples <samples.json> --models <models.json> --output .runtime/ocr-review/results
```

输入文件由可信本地维护者准备，不从玩家配置加载。图片和三个模型文件须匹配 SHA-256。每条样本包含 ID、原文件、group、calibration/held_out、预期是否通过、类别、入口和 baseline/method 两套规则。来自同一画面、裁剪或增强的样本必须在同组；同组不能跨分区，同一图片不能冒充另一组。

每套模型由独立子进程运行，仅使用 SavedImages 控制器。推理期间禁止网络连接和真实 ADB。评测完整复合识别守卫，通过独立 DoNothing 入口避开业务 `on_error` 把任务成功混成识别成功；不会点击设备。一次预热后重复三次，输出 JSON、无图片及原始 OCR 的 HTML、模型体积、初始化时间、内存和整页识别 P95。日志及原始 JSON 仍属于本地资料。

固定文字、数字/身份、动态文字分别选择模型。门槛为留出正负样本齐全、零危险误通过、原有成功无倒退、至少改善一张真实失败原图、P95 比基线至多增加一秒，并继续满足原业务预算。任何条件未满足都保留原模型；MaaFramework 仍为 5.13.0。

本轮比较 MaaCommonAssets 的 PP-OCRv5 mobile/server、PP-OCRv6 small/medium，固定提交 `dabcd4681ac990dc4361de26416d986abd80e4aa`。上游仓库为 MIT，PaddleOCR 项目许可证为 Apache-2.0（本轮核对 v3.2.0 LICENSE）；下载权重仅在离线工作区，没有进入候选运行包。原 R53 det/rec 与上游 v4 二进制一致；字典内容一致，仅换行不同。不得从上游通用榜单推断游戏识别效果。

本轮没有 2026-10-15 18:40 失败的原图，也缺少数字/身份和动态文字的真实失败样本，因此三类均保留 R53 权重。保存画面不等于真实游戏验收。模型兼容、识别准确度、原生任务成功和实际业务结算是四种不同结论。
