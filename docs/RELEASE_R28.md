# r28 结果检查点与安全收尾（GUI 沿用2.16.5）

原问题的共性是：消费意图已落账，但结果返回、弹窗关闭或次数读回异常，会让已确认的消费一直停在in_flight。本版本在深渊、所有主线/深域预设和活动扫荡的专属结果帧确认时，先原子写入并fsync检查点，再执行关闭与后续导航。检查点绑定账本完整字节前缀、本次意图/报价、原生唯一成功消费动作、当前结果帧哈希与三项严格OCR锚点，不依赖整条导航native_ok。

新的显式Start会核验已有检查点，保留原账前缀并追加“消费结果已确认、后置次数/主页仍未确认”的阶段终止记录。它不是原业务完整成功；不补造余次、返回或旧运行成功。随后仅走专属结果确认/限定商店取消，或当前原页面/主页的非消费恢复，再完整读取当前列表。未知页面、停止、设备/证据漂移仍截断；不会重发原消费。

同日有限次数必须当前目标完成且身份一致才可跳过继续，其他情况仍阻断。正常不限次预设若旧后置过程未确认，同日也不重复发送。后续周期仍须新的当前观察、报价和独立新意图；时间变化不能解除真正unknown。中断的临时次数只在原槽、原完整身份及预期原值/目标值下恢复；旧恢复与新执行各自核验还原。r27维护过的旧记录及其证据保持。

日志区分result_verified_followup_incomplete与真正unknown_settlement。当前回调已停止/撤权时不强行继续；下次Start进入新的有效Owner作用域核验与收尾。只有当前安全读回及主页验证后才允许后续模块。

离线验收涵盖结果后异常、停止、进程退出、证据破坏、防重、新周期、次数恢复与原生结果/商店/共享Context。安装仅更新本地程序，不改旧账、设置、顺序或日志；没有发送新的实机消费，也未宣称真实今日整链完成。正式日程按钮语义、GUI显示映射和真实程序集沿用r27/r26。
