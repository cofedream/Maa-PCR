# R54 角色筛选状态修复

本次保留原 v4 模型和 MaaFramework 5.13.0。修改角色筛选状态与点击后的稳定等待，不改变账号、地图、角色身份、金额、结算和未知不重发规则。候选仍使用 R54，实际安装和实机结果以本轮匹配清单及收据为准。

## 原因与修改

失败原帧中，点击波纹覆盖了“有效效果”和相邻属性按钮。旧外层识别根据 OCR 文字框扩出的区域判断选中态。首帧缺少一个字，使范围移动，把相邻暗属性判为选中；随后完整角色读回耗尽等待预算。

战斗和 Boss 页现在使用固定布局中的按钮矩形判断选中态。颜色条件沿用固定上游：B≥120、B−R≥24、G−R≥8，每 4 像素抽样，蓝色覆盖率至少为 0.35。矩形分别映射四条边，Boss 使用其专用位置。只有一个按钮满足条件时才接受。多个或没有选中证据时返回未知，不选择覆盖率最高者。开局页保留原来已验证的 OCR 定位路径；其他功能共用的颜色判断保持。

筛选点击保留页面、按钮文字和 Boss 队伍页校验，免去点击前无关的整页头像扫描。点击一次后，使用一次原生局部静止检测，预算最多 2.5 秒，并显式检查返回值。调用前后检查 Stop。原生检测需要先后取两帧；不再将请求拆成可能短于首帧截图耗时的片段。随后读取新画面，继续要求目标筛选、角色身份和连续稳定证据。

点击、局部稳定等待和反馈共用原来的 12 秒总预算。超时、错误筛选、页面变化或 Stop 都不会重新发送点击。同步 SDK 调用只能返回后检查时间，实际墙钟耗时可能超过请求超时或总预算，随后停止且不再输入；不能承诺硬实时取消。

## 验证范围

公开合成回归覆盖缺字、相邻波纹、灰蓝未选中按钮、双选中、无选中、错误页面、局部和区域外动画、持续动画超时、Stop，以及点击不重发。另用实际 Maa SDK 为每帧加入 0.55 秒截图延迟，复核静止、波纹消退、持续运动及进入原生等待后的 Stop。私有离线回放覆盖本次两张失败原帧、位移、亮度、压缩与波纹变体，另复核历史 ALL、开局、成员身份和 Boss 页面，以及真实原帧的慢截图点击反馈。

测试按固定预期核对，保留修前失败和后续通过记录。同源增强图不是独立真实样本。SavedImages 中的一次合成点击也不是设备输入。真实游戏必须在匹配候选安装后另行验收，不能由回放结果推断一次通关。

私有图片和原始 OCR 只保存在本地 `.runtime`，不进入运行包或匹配源码包。安装只更新拥有清单中的程序文件，保留全部配置、凭据、账本、检查点、日志和历史记录。原同编号候选替换须绑定精确新旧清单；普通降级与进程检查保护保持。
