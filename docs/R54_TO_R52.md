# R54 测试版转正式 R52

这条路径只用于本机已确认的 `v0.1.7-r54-candidate / R54` 转到验收通过的正式 R52。当前只实现并离线验证转换工具，不发布正式 R52，也不修改现用 R54。正式公开基线仍为 R51。

## 玩家使用

正式 R52 通过验收并生成专用转换包后，正常退出 Maa PCR 和 Agent。把可信转换包解压到原安装目录之外，运行 `convert.bat`，输入原安装目录。工具只更新清单拥有的程序文件，不自动打开界面或执行游戏任务。完成后按原快捷方式打开软件。

R54 自带的旧更新页和普通补丁入口会拒绝低编号 R52，必须使用这个专用入口。不要直接解压覆盖原程序，不要改清单编号，也不要把配置搬到新目录绕过账本。

如转换被中断，保留原目录、转换包和 `.runtime/player-maintenance`，运行同一转换包中的 `recover.bat`。它只在来源、目标、备份与当前程序字节均可核对时恢复到原 R54；未知文件冲突会停止，不自动覆盖。恢复成功后才能重新尝试转换。没有未完成事务时，恢复入口不会执行降级。

## 校验与数据保护

来源固定为 R54 慢截图修正版，清单 SHA256 为：

```text
2b653ffdd0c1378497204ef4f1c3f3f48313a3ba39f298d30fad168153280578
```

其他 R54 构建不能自行提供哈希来获得转换资格。目标必须是 R52、正式版本号、`player_test_release`、`distribution_ready=true`、无阻断项且带有效格式的验收记录。转换包再固定目标清单、差分 ZIP 和维护器文件的 SHA256。目标维护器必须与验收程序清单中的文件一致。

转换和恢复复用原维护器的默认进程检查、程序哈希、路径限制、仓库绑定、未拥有文件冲突检查、持久化事务、回滚备份和未知字节拒绝规则。普通更新仍要求 revision 递增；原同编号候选替换规则保持不变。所有 `runtime/python/` 程序文件必须与冻结 R54 完全一致，以便使用原内置解释器执行外置维护器，并在中断后恢复。未来若确实需要更换这套 Python 运行时，必须另行验证外置解释器方案，本转换包会直接拒绝。

配置、任务顺序、加密凭据、日志、截图、账本、未知记录、检查点和计数器不进入更新载荷，也不由转换工具改写或补结算。维护器只新增自己的事务目录及回执。原账号、地图、金额、结算、Stop 和未知不重发等业务保护保持。

SHA256 用于损坏检查和精确版本绑定，不是发布者签名；转换包仍须来自可信发布渠道。

## 维护者生成

先按既有流程完成正式 R52 的程序、源码和验收清单。不得把当前 R54 的阻断项或实机缺口改成已通过。转换工具不会替代正式发布验收。

在匹配源码目录执行：

```powershell
python -X utf8 -B scripts/build_r54_release_bridge.py --base-manifest FROZEN_R54/package-manifest.json --target ACCEPTED_R52_PLAYER --output .runtime/r54-to-r52-bridge
```

工具校验冻结来源、正式目标和目标工具文件，复用差分构建器生成精确补丁，再封装独立转换入口及恢复入口。输出目录必须是新目录。该步骤不安装、不联网、不创建 GitHub Release。最终附件为输出目录中的 `Maa-PCR-R54-test-to-R52-formal-bridge.zip`。

本次完整入口演练使用冻结 R54 的全部程序文件和明确标为合成测试的 R52 目标。合成目标、合成验收记录与测试转换 ZIP 全部留在 `.runtime`，不可作为正式发布产物。最终正式目标清单确定后，需要重新生成绑定它的转换包，并复验隔离安装与恢复。
