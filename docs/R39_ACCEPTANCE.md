# R39 验收

速度优化已实现，整体日常提速和新完整游戏链实机对照尚未验证，不宣称提速百分比。实机R38/R39性能对照、六个游戏日与40%均不作为发布前置条件。消费确认、结算和unknown保护保持；发布仍须通过下述离线、GUI、更新/恢复、构建和精确载荷检查。

## 离线

合成测试覆盖新帧错误页面/槽位、同回调完整参数去重、负例与异常传播、预设中间边界、停止和未知结果禁止重发。批量OCR仅离线实验，未验证不启用；纯观察节点可以去掉无业务作用的默认等待，输入后的稳定等待、识别阈值、消费确认和结算保护保留。

只验证改动影响范围，并复用未变化的有效证据。需要计时的回放先预热，再交替对照，记录实际预热与重复次数、总耗时、读回/确认耗时、OCR/截图/输入次数、业务字段及可用的统计值。没有测得的指标记录为缺失，不填0；私人原帧不进入公开仓库。离线速度不代替实机验收。

## 可选实机对照

实机性能测量作为后续可选工作，不阻断本次发布，也不自动触发游戏操作。若以后进行对照，固定一个设备/账号、任务顺序、预设与目标，取得完整可比的R38/R39样本；按波动或正确性疑点追加同一候选的平衡交替样本。每次保留完整原始报告、安装清单、配置哈希和独立工作量审核。版本切换复制最新账本，不回滚或清空未知记录，不绕过已完成额度。

失败或不可比样本保留并注明排除原因，不用额外同日消费补齐；完整但较慢的可比样本仍纳入统计。候选若改动影响执行，重新冻结并重新计候选批次，不能拼接不同候选的成绩。

性能对照审核：纳入对照的候选链均完整通过，中位耗时小于基线，并根据实际差值、最长耗时及波动审核提速是否可观；这些规则只用于可选性能测量，不是发布门槛。人工核实无重复消费、无错误结算。体力不足等正常跳过保留原业务结果；若导致消费工作量不同则不充当完整可比对照。测量仅指选定的已支持日常链，不宣称游戏全部日常覆盖。

`scripts/daily_acceptance.py REGISTRY.json` 只读取证据，不运行游戏。registry含`samples`数组，每项字段为`revision`、`report_path`、`report_sha256`、`manifest_sha256`、`config_sha256`、`workload_sha256`及`review`；review中的`live_device`、`comparable_workload`、`no_duplicate_consumption`、`no_wrong_settlement`须由实际证据审核后为true。对照形成且审核认为提速可观后，才把registry顶层`meaningful_speedup_reviewed`填为true；没有该审核时保持pending，完整对照未提速时为failed。排除项带`excluded_reason`，仍保留报告哈希。相对报告路径相对registry目录。

不得把合成测试的review或伪造数据用作真实验收。性能工具输出pending/failed时退出码2，只有对照达标为0；该输出不控制发布。历史registry、账本及真实验收结果保持原样。原始证据仅本地保存，公开`delivery/acceptance.json`如实记录检查结果和未测指标。

## 发布闸门

公开测试通过、隔离更新/恢复通过、两配置GUI实际验收和干净构建通过，并绑定精确载荷后，才能把`delivery/acceptance.json`设为passed并发布v0.1.0。这里的passed只表示这些发布检查通过，不表示实机性能或新完整游戏链已通过；未测指标保持`live_valid_game_days=0`、`candidate_to_baseline_ratio=null`、`meaningful_speedup_reviewed=false`，不为发布填写虚假成绩。用`accepted_owned_payload_sha256`绑定冻结候选的程序文件清单；代码、资源、运行时或编译字节变化时，只补验证受影响范围，未变化证据按原范围复用，但不得直接给新载荷沿用旧passed标记。发布状态元数据的变化不改程序载荷绑定。CI重建若字节不同须核对变化影响，或仅校验并上传已经验收的同tag载荷。GUI加载、真实游戏行为和安装升级是独立证据，不互相代替。真实Release下载更新及私态保全在发布后回验，尚未验证时如实标注。
