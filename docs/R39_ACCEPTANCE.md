# R39 验收

目标：相同设置、设备和可比日常工作量下，相对 R38 整体耗时中位数降低40%，且不增加重复消费或错误结算。当前是开发候选，未达到目标不发布稳定版。

## 离线

合成测试覆盖新帧错误页面/槽位、同回调完整参数去重、负例与异常传播、预设中间边界、停止和未知结果禁止重发。批量OCR仅离线实验，未验证不启用；不批量降低阈值或归零等待。

每类回放预热5次，原版/候选交替20对，记录总耗时、读回/确认耗时、OCR/截图/输入次数、业务字段和median/P95。没有测得的指标记录为缺失，不填0；私人原帧不进入公开仓库。离线速度不代替实机验收。

## 实机对照

固定一个设备/账号、任务顺序、预设与目标；跨6个有效游戏日交替运行R38/R39，各3次。每次保留完整原始报告、安装清单、配置哈希和独立工作量审核。版本切换复制最新账本，不回滚或清空未知记录，不绕过已完成额度。

失败或不可比样本保留并注明排除原因，不用额外同日消费补齐。候选若改动影响执行，重新冻结并重新计候选批次，不能拼接不同候选的3次通过。

验收：3次候选均完整通过；候选中位数不超过基线60%，最长一次不高于基线最长一次；人工核实无重复消费、无错误结算。测量仅指选定的已支持日常链，不宣称游戏全部日常覆盖。

`scripts/daily_acceptance.py REGISTRY.json` 只读取证据，不运行游戏。registry含`samples`数组，每项字段为`revision`、`report_path`、`report_sha256`、`manifest_sha256`、`config_sha256`、`workload_sha256`及`review`；review中的`live_device`、`comparable_workload`、`no_duplicate_consumption`、`no_wrong_settlement`须由实际证据审核后为true。排除项带`excluded_reason`，仍保留报告哈希。相对报告路径相对registry目录。

不得把合成测试的review或伪造数据用作真实验收。工具输出pending/failed时退出码2，只有完整达标为0。原始证据仅本地保存，公开`delivery/acceptance.json`只记录审核结果和指标。

## 发布闸门

公开测试通过、隔离更新通过、两配置GUI实际验收、干净构建通过、6个实机游戏日和40%目标全部达标后，才把`delivery/acceptance.json`设为passed并发布v0.1.0。公开验收还须用`accepted_owned_payload_sha256`绑定冻结候选的程序文件清单；代码、资源、运行时或编译字节变化时，不复用旧passed结果。发布状态元数据的变化不改程序载荷绑定。CI重建若字节不同须重新验收，或仅校验并上传已经验收的同tag载荷。GUI加载、真实游戏行为和安装升级是独立证据，不互相代替。
