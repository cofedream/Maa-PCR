# R39 离线更新说明

R39为待验收候选，对外版本目标为`v0.1.0 / R39`；实际发布以验收结果为准。软件内检查、ZIP导入与恢复共用清单保护及外置维护器，详见[更新与恢复](UPDATES.md)。R38首次升级必须使用引导包内的`first-update.bat`，不能沿用旧入口替换Python原生文件。

“高级设置 → 多显示屏映射校验”默认关闭；非默认显示屏可开启，无法确认映射会停止。设备、游戏前台、画面比例及停止保护始终保留，设置按配置保存。

# 离线补丁更新

## 玩家操作

1. 保留原软件目录及`.runtime`，确认游戏任务已空闲。
2. R39及后续版本在软件更新页选择离线ZIP；也可正常退出软件和Agent后运行`导入补丁包.bat`。
3. 选择来自可信Release的运行包或精确补丁ZIP，等待校验和外置安装完成。R38请改用前述引导包。

不要解压补丁覆盖程序，不要把自己的配置复制到新目录来绕过旧记录。
离线ZIP导入不联网；成功后只重启GUI，不自动执行游戏任务。

完整运行包适合首次安装，也可作为同布局的完整更新输入。差分补丁只包含变动程序文件及更新manifest，要求基础revision和清单哈希精确匹配；不匹配时选择完整运行包，不猜测基线。

## 保留与失败处理

仅更新 manifest 所有的程序载荷，删除的程序资源也按 manifest 处理。玩家配置、任务顺序、日志、截图、账本与未决记录不属于更新载荷，不重置也不迁移。未知业务结果不会由程序升级自动结算。

版本不符、文件被修改、软件仍运行或校验失败会拒绝更新。写入失败时按备份回滚程序；若回滚也出现冲突，保留 `.runtime/player-maintenance` 和错误提示，交给维护者处理。不要清空备份或删除事务标记。

## 维护者制作小补丁

匹配源码中的 `scripts/build_pcr_player_patch.py` 使用两个完整、经过校验的程序目录生成差分 ZIP：

```powershell
python -X utf8 -B scripts/build_pcr_player_patch.py --base OLD_PLAYER --target NEW_PLAYER --output PATCH.zip
```

目标 revision 必须递增，布局和产品标识保持一致。工具只取 manifest 所有的变动文件，不打包玩家的私人数据。生成后应在独立旧版本副本中实际导入，验证配置、任务顺序和业务记录哈希保留，再交付。

SHA256 防止损坏并绑定基础版本，不是发布者签名。R39新增软件内稳定版检查和点击安装，统一使用Maa-PCR的GitHub Release及外置维护器，见 [更新与恢复](UPDATES.md)。R38首次升级改用bootstrap外层的first-update.bat，不使用正在占用内置Python的旧入口直接更换Python原生文件。离线ZIP仍使用同一清单保护，不直接解压覆盖。
